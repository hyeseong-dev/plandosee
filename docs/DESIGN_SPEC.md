# plandosee · 디자인과 사용 흐름 가이드

작성일: 2026-09-10 · 버전: 0.1 · 상태: 디자인 제안, 실제 화면 시안·구현 전

## 확정된 방향과 이번 초안

사용자가 직접 정한 방향은 **모던한 느낌, 귀여운 테마, 뻔하거나 낡아 보이지 않으면서 명확한 글씨체, 각진 인상을 피하는 UI/UX, 과제 원칙 준수**다.

이 문서는 그 방향을 구현 가능한 기준으로 옮긴다. 아래 테마·서체 조합·색상·여백·크기·동작 수치는 AI 제안이며 아직 사용자가 선택한 최종 디자인이 아니다. 선택 질문의 답이 없는 시점에 ‘작은 정원’을 초안으로 사용했다.

## 테마 제안 · 작은 정원

**기록이 조금씩 쌓이는 밝고 조용한 공간.** 잎과 새싹의 둥근 실루엣, 흰 화면, 아주 옅은 초록과 살구색을 사용한다. 실제 읽을 내용은 짙은 녹색 글자로 선명하게 둔다. 프로젝트 이름은 `plandosee`를 유지하고 ‘작은 정원’은 콘셉트 설명으로 사용한다.

정원은 표현 방식이다. 할 일·실행 기록·돌아보기를 이해하기 위해 식물의 성장 규칙을 배울 필요가 없도록 한다. 기본 메뉴와 버튼은 ‘계획’, ‘할 일 추가’, ‘실행 기록’, ‘돌아보기’로 명확하게 표시한다.

| 요소 | 표현 제안 | 적용 범위 |
| --- | --- | --- |
| 귀여움 | 둥근 잎 모양, 작은 새싹 캐릭터, 넉넉한 곡률 | 빈 화면, 제목 옆 작은 장식, 저장 성공의 짧은 반응 |
| 모던함 | 깨끗한 단색 면, 넉넉한 여백, 강약 있는 한글 크기, 절제된 그림자 | 전체 레이아웃 |
| 개성 | 계획과 실제가 짝지어진 기록 행, 개선점 한 줄의 전달 모습 | 핵심 데이터 화면 |
| 친근함 | 짧고 구체적인 한국어, 입력 중 문맥 유지 | 폼·오류·완료 메시지 |
| 명확함 | 상태명·숫자·단위·범위 표시, 선택 상태와 포커스 구별 | 모든 기능 요소 |

찢어진 종이·낡은 종이 질감·세피아색·손글씨 본문은 이번 방향에서 제외하는 제안이다. 여러 종류의 이모지를 아이콘 시스템 대신 혼용하거나 모든 면을 스티커로 덮는 표현도 피한다. 사용자가 요청한 귀여움은 읽기 쉬운 형태와 작은 반응으로 구현한다.

작은 캐릭터는 작업이 늦어졌다는 이유로 시들거나 벌을 주는 표정이 되지 않는다. 완료율을 식물 건강 수치로 해석하거나 실제 기록에 없는 성취를 만들어내지 않는다.

## 차별화할 세 가지 화면 표현

### 1. 계획과 실제를 짝으로 읽는 기록

할 일 하나의 예상과 실제를 같은 행 안에 놓는다. 왼쪽은 할 일 내용·마감·예상, 오른쪽은 실제 시간과 기록 진입점이다. 미기록 상태는 ‘실행 기록 없음’으로 표시하여 실제 0분과 구별한다. 돌아보기 합계의 빈 값 0 규칙과 개별 행의 설명은 양립할 수 있다.

예시 문구는 합성 화면 설명이며 사용자의 실제 기록이 아니다.

| 할 일 | 계획 | 실제 | 다음 행동 |
| --- | --- | --- | --- |
| 발표 자료 목차 정리 | 예상 30분 · 오늘 마감 | 실제 45분 · 차이 +15분 | 기록 보기 |
| 참고 자료 읽기 | 예상 20분 · 마감일 없음 | 실행 기록 없음 | 실행 기록 |

실제 시간이 예상보다 적거나 많다는 사실을 곧바로 성공·실패로 칭하지 않는다. 계획의 ‘성공 기준’과 시간 차이는 다른 정보다. 색상만으로 평가를 전달하지 않고 ‘예상보다 15분 더 사용’처럼 구체적으로 쓴다.

계획 수정 이력과 할 일 예상 시간은 구별한다. 현재 할 일의 예상 시간을 과거 계획 시점 값이라고 표시하지 않는다. 할 일 버전 보존까지 추가하려면 별도 설계 결정이 필요하다.

### 2. 숫자에서 실제 기록까지

돌아보기의 각 숫자에 이름, 단위, 설명, ‘해당 기록 보기’를 함께 제공한다. 식물·꽃 그림의 개수로 집계 숫자를 대체하지 않는다.

계획 수에는 ‘등록한 할 일’이라는 설명을 붙여 계획 엔터티 개수와 혼동하지 않게 한다. ‘막힘’은 막힌 이유의 개수가 아니라 해당 할 일 수다. 숫자를 누르면 관련 기록과 필터 설명을 보여주고, 이전 화면의 선택 계획과 스크롤 맥락으로 돌아올 수 있게 한다.

시간 차이는 크기가 0인 경우에도 선택할 수 있는 텍스트 값이다. 차이 상세에서 할 일별 예상과 실행 기록별 실제를 대조할 수 있게 한다. 0일 때도 빈 데이터와 정확히 같은 소요 시간인 경우를 설명으로 구별한다.

### 3. 다음 계획에 붙는 한 줄

돌아보기 하단에 ‘다음에는 무엇을 바꿔볼까요?’라는 한 줄 입력 영역을 둔다. 저장한 개선점 한 건을 다음 계획에 가져오면 부드러운 색상의 작은 영역에 ‘이전 돌아보기에서 가져왔어요’와 원래 기록 링크를 표시한다.

실제 연결은 사용자가 고른 대상 계획과 서버에 저장된 자료로 구성한다는 제안이다. 입력하지 않은 문장을 자동으로 사용자의 결론처럼 채우지 않는다. 전달 버튼의 재시도로 같은 개선점이 중복 부착되지 않게 하는 검사는 별도 구현 제안으로 관리한다.

## 정보 구조와 대표 화면

| 위치 | 담을 내용 | 구성 의도 |
| --- | --- | --- |
| 상단 | 작은 워드마크, 오늘/계획/돌아보기, 자료 내보내기 | 세 가지 주요 이동을 일관되게 유지 |
| 첫 화면 안내 | 원문 공개 안내 전체 문장 | 저장 전에 공개 범위를 인지 |
| 페이지 도입 | 선택한 계획과 기간, 페이지 제목, 주요 행동 하나 | 현재 작업 대상을 빠르게 파악 |
| 주 콘텐츠 | 계획/실제 기록, 선택한 화면의 폼 또는 돌아보기 | 가장 큰 면적을 사용자 자료에 사용 |
| 보조 영역 | 기록 상세, 개선점, 원본 계획 정보 | 필요할 때 읽는 정보와 주 행동 연결 |

### 오늘 · 데스크톱

상단에서 계획을 선택하고 제목은 ‘오늘의 계획과 실제’로 제안한다. 오늘 날짜는 `서울 기준`이라는 짧은 설명과 함께 표시한다. 페이지 위에는 공개 안내를 놓고, 주 콘텐츠는 좁은 사이드바가 아닌 넓은 기록 영역으로 구성한다.

기록 영역 위에 검색, 상태·태그 등의 필터, 현재 정렬 기준을 둔다. 첫 버전의 기본 정렬 제안은 [D-08](PROJECT_PLAN.md#정책-제안과-미결정-사항)을 따른다. 정렬 설명은 일부 순서를 생략하지 않고 ‘미완료 먼저 → 마감 빠른순(없음 뒤) → 높은 우선순위 → 생성순 → ID순’처럼 펼쳐 볼 수 있게 한다. 사용자 정의 드래그 순서처럼 보이는 핸들은 이 기능을 구현하지 않는 동안 표시하지 않는다.

각 행에는 내용, 마감일, 우선순위·태그, 예상 시간과 실제 시간, 완료 상태가 있다. 완료 컨트롤과 상세 열기 영역은 분리한다. 행 전체를 눌렀다고 완료가 바뀌지 않는다. 긴 제목은 줄바꿈하고, 실제 전체 내용은 상세에서 확인할 수 있다.

하단 또는 측면에 ‘돌아보기’로 가는 짧은 안내를 둔다. 현재 기록이 없어도 캐릭터보다 ‘할 일 추가’가 먼저 눈에 들어오게 한다.

### 계획 · 작성과 수정

기간·우선순위·성공 기준·계획 자체 예상 시간을 하나의 읽기 쉬운 폼으로 묶는다. ‘예상 시간: 할 일 합계와 별도로 저장되는 계획값’이라는 설명을 제공한다. 단위는 입력창 옆에 표시한다.

수정할 때 현재 버전을 명확히 보여주고, 저장한 뒤 수정 전 값에 접근할 수 있게 한다는 UI 제안이다. 이전 이력은 읽기 전용으로 표현한다. 과거 계획을 현재 값으로 복구하는 기능은 원문에 없으므로 기본 버튼으로 넣지 않는다.

빈 칸을 모두 채워야 하는지, 기간 역전·음수 시간·글자 길이를 어떻게 처리할지는 [D-13](PROJECT_PLAN.md#정책-제안과-미결정-사항) 및 필드별 유효성 설계에서 확정한다. 안내 없이 필수 조건을 숨겨두지 않는다.

### 실행 기록 · 상세 패널

데스크톱에서는 옆 패널, 작은 화면에서는 전체 높이의 상세 화면으로 열리는 구성을 제안한다. 상단에 할 일 내용을 유지하고 시작·종료·실제 시간·막힌 이유를 묶는다. 자정을 넘는 기록을 입력할 수 있도록 시각만이 아닌 날짜도 확인 가능하게 한다.

실제 시간 계산 제안은 종료 − 시작이다. 결과 옆에 단위를 표시하고 계산값을 저장한다. ‘계획 예상 30분’은 참고 정보로 보여주며, 실행 저장이 계획 수정처럼 보이지 않게 한다. 완료 버튼만 눌러 가짜 시작·종료 값을 생성하지 않는다.

저장 중에는 중복 요청을 완화하는 상태를 표시하되, 중복 방지의 최종 보장은 서버 설계에서 다룬다. 실패하면 입력한 내용을 남기고 오류와 재시도 동작을 제공한다. 아직 저장되지 않은 내용을 ‘저장됨’으로 표시하지 않는다.

### 돌아보기 · 읽을 수 있는 결과

상단에 선택된 계획과 대상 범위를 먼저 둔다. 그 아래 계획 수·완료·지연·막힘을 하나의 요약 영역 안에서 정렬하고, 예상·실제·차이는 각각 값과 단위가 있는 비교 영역으로 둔다. 별개의 대형 통계 카드 여러 장이 화면을 지배하지 않도록 하는 배치 제안이다.

계획 기간과 집계 기간 정책은 다를 수 있으므로, 제안 D-03을 채택한다면 ‘이 계획의 삭제되지 않은 할 일과 전체 실행 기록 기준’이라고 표시한다. 서울 기준 오늘의 변동은 지연 집계에도 영향을 준다.

중간에는 집계에서 선택한 실제 기록을 보여주고, 하단에는 사용자가 적는 돌아보기와 다음 계획으로 보낼 개선점 한 건을 둔다. 통계는 현재 상태 기준으로 계산하고, 메모의 저장 시각과 구별한다는 제안이다.

## 서체 제안

한글이 본문과 제목의 중심인 제품이므로 한글 모양·줄바꿈·숫자 판독성을 먼저 본다. 영어 헤드라인만 새로운 폰트로 바꾸고 한국어 화면은 기본 폰트로 남기는 결과를 피한다.

| 역할 | 후보 | 사용 제안 | 선택 이유 |
| --- | --- | --- | --- |
| 제목·짧은 브랜드 문구 | LINE Seed KR Bold | 700, 24–40px 범위 | 둥근 형태의 친근한 인상을 제목에서 표현 |
| 본문·폼·버튼·수치 | Wanted Sans | 400/500/600/700 중 필요한 굵기, 본문 16px | 한글과 라틴을 함께 지원하며 본문 가독성과 현대적인 인상을 조합 |
| 대체 폰트 | 시스템 sans-serif | 다운로드 실패 시 | 폰트가 없어도 내용·입력이 유지됨 |

LINE 공식 소개는 LINE Seed KR의 둥근 형태와 한글·영문 조화를 설명한다. Wanted Sans 공식 저장소는 한글·라틴 지원, 7개 기본 굵기와 가변 글꼴 제공을 설명한다. 두 후보 모두 공식 배포처에서 SIL Open Font License를 안내한다. 실제 적용 때 사용할 파일과 동봉 라이선스를 확인하고 출처를 남긴다. [LINE Seed 공식](https://seed.line.me/index_kr.html), [Wanted Sans 공식 저장소](https://github.com/wanteddev/wanted-sans/blob/main/packages/wanted-sans/README.md).

위 설명은 서체 후보의 공식 정보와 이 프로젝트를 위한 미적 판단을 구분한 것이다. 이 서체 조합이 다른 과제에 사용되지 않았다는 주장은 하지 않는다. 개성은 서체뿐 아니라 화면 구성과 기록 경험까지 함께 만든다.

| 텍스트 역할 | 데스크톱 제안 | 모바일 제안 | 행간 |
| --- | --- | --- | --- |
| 페이지 제목 | 36–40px / 700 | 28–32px / 700 | 1.25–1.35 |
| 영역 제목 | 22–24px / 700 | 20–22px / 700 | 1.35 |
| 본문·입력 | 16px / 400–500 | 16px / 400–500 | 1.55–1.65 |
| 버튼·상태 | 15–16px / 600 | 15–16px / 600 | 1.4 |
| 보조 설명 | 14px / 400–500 | 14px / 400–500 | 1.5 |
| 주요 집계 | 32px / 700 | 28px / 700 | 1.2 |

폰트 크기는 구현 시 rem 기반으로 대응하고 글자 확대를 허용한다. 공개 안내·실패 메시지는 작은 장식 텍스트로 축소하지 않는다. 얇은 웨이트를 본문에 사용하거나 인위적으로 늘이고 기울이는 처리는 하지 않는 방향을 제안한다.

적용 시 필요한 WOFF2 파일을 라이선스와 함께 자체 제공하고 `font-display: swap`을 사용하는 방안을 검토한다. 실제 숫자에서 고정폭 숫자 기능 지원 여부를 확인한 뒤 적용하며, 지원을 확인하지 않은 기능을 사용했다고 기록하지 않는다. 서체 파일은 이번 문서 작업에서 내려받거나 앱에 설치하지 않았다.

## 색상 제안

파스텔은 배경과 작은 강조에 사용한다. 중요한 글자는 충분히 짙게 둔다. 아래 토큰명과 값은 교체 가능한 디자인 초안이다.

| 역할 | 토큰 | 값 | 용도 |
| --- | --- | --- | --- |
| 전체 배경 | canvas | `#F7F8F2` | 밝고 맑은 회백색 |
| 주 콘텐츠 | surface | `#FFFFFF` | 읽기·입력 면 |
| 기본 글자 | ink | `#20362D` | 제목·본문·숫자 |
| 보조 글자 | text-secondary | `#58685D` | 설명·단위·날짜 |
| 주요 행동 | primary | `#365E47` | 저장·추가 버튼, 흰 글자 |
| 계획 강조 | mint-soft | `#DCEEDD` | 계획 영역의 옅은 강조 |
| 실제 기록 강조 | apricot-soft | `#F6DFC5` | 실행 영역의 옅은 강조 |
| 돌아보기 강조 | lilac-soft | `#E8E3F5` | 개선점·선택 문맥 |
| 안내 배경 | notice-soft | `#F7EBC0` | 공개 안내 |
| 지연·오류 글자 | critical-ink | `#9C4141` | 명확한 상태명과 함께 사용 |
| 지연·오류 배경 | critical-soft | `#F6E3DF` | 옅은 상태 영역 |
| 장식 경계 | border-soft | `#AFBCB1` | 구역 구분; 조작 가능성의 유일한 표시로 사용하지 않음 |
| 포커스 | focus | `#60508A` | 키보드 포커스 외곽선 |

초안의 기본 색 쌍을 sRGB 상대 휘도 공식으로 계산했다. 실제 화면·투명도·호버 상태·폰트 렌더링을 검사한 결과는 아니다.

| 전경 / 배경 | 계산 대비비(표시만 소수 2자리) | 용도 |
| --- | --- | --- |
| `#20362D` / `#F7F8F2` | 12.09:1 | 기본 글자 |
| `#58685D` / `#FFFFFF` | 5.91:1 | 보조 글자 |
| `#FFFFFF` / `#365E47` | 7.37:1 | 주요 버튼 |
| `#9C4141` / `#F6E3DF` | 5.23:1 | 지연·오류 |
| `#60508A` / `#FFFFFF` | 6.97:1 | 흰 면의 포커스 |

일반 텍스트 대비 4.5:1 이상을 디자인 목표로 제안한다. 이는 원문 44개에 추가된 확정 의무가 아니다. 기준과 계산 방식은 [W3C 대비 최소 지침](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참고했다. 일부 색 쌍의 계산만으로 제품 전체가 WCAG를 준수한다고 판정하지 않는다.

## 형태·여백·움직임

| 요소 | 수치 제안 | 사용 원칙 |
| --- | --- | --- |
| 주요 면의 모서리 | 24–28px | 넓은 기록 영역에만 큰 곡률 |
| 입력창·기록 행 | 14–18px | 줄 정렬과 조작 영역을 유지 |
| 버튼 | 16px, 탭·칩은 pill 허용 | 중요 버튼의 크기와 글자 우선 |
| 간격 | 4 / 8 / 12 / 16 / 24 / 32 / 48px | 관계가 가까운 요소를 붙이고 영역 사이에 여백 |
| 그림자 | 약한 하나의 단계 | 기록 영역과 떠 있는 패널의 깊이 구별 |
| 아이콘 | 20–24px, 둥근 선 끝 | 같은 굵기·시각 크기를 유지, 중요한 동작은 텍스트 병기 |
| 조작 영역 | 최소 44×44px 목표 | 작은 아이콘 주변에 충분한 클릭 영역 |
| 전환 | 140–220ms 제안 | 색·투명도·짧은 위치 변화 중심 |

귀여운 비대칭은 작은 장식에서 사용한다. 입력창·텍스트·숫자를 기울이거나 버튼을 불규칙하게 배치하지 않는다. 모든 것을 타원으로 만들기보다 기록의 정렬과 여백을 유지하는 방식으로 부드러운 인상을 만든다.

완료 애니메이션은 데이터 저장 성공 이후 짧게 표현한다. 애니메이션 횟수로 완료 기록을 생성하거나 그 자체를 성공 증거로 쓰지 않는다. 반복 흔들림·자동으로 움직이는 배경은 기본 범위에서 제외하는 제안이다. `prefers-reduced-motion` 설정에서는 장식 동작을 줄이고 텍스트 상태는 동일하게 전달한다.

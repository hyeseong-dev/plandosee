# PlanDoSee 요구사항·검증 명세

문서 상태: **구현 전 초안** · 기준일: 2026-09-10 · 기준 원문: [constitution.txt](../constitution.txt)

이 문서는 공통 과제의 44개 인수 조건을 보존하면서, 서로 다른 구현자가 같은 결과를 확인할 수 있도록 관찰 가능한 요구사항과 검사를 연결한다. 아래의 검사와 증거는 **실행할 계획**이며, 아직 구현·시험·배포 완료를 뜻하지 않는다. 기능의 의미는 원문을 따르고, 화면 구성과 시각 표현에는 사용자가 확정한 개성을 반영한다.

## 1. 근거와 결정 상태

| 표시 | 의미 | 이 프로젝트에서의 적용 |
| --- | --- | --- |
| 원문 확정 | 과제 원문에 실제로 적힌 의무 | 아래 추적표의 44개 조건. 원문 열은 문장을 그대로 보존한다. |
| 사용자 확정 | 대화에서 사용자가 직접 정한 방향 | 모던하고 귀여운 테마, 명확하지만 낡아 보이거나 뻔하지 않은 글씨체, 딱딱하고 각진 UI/UX 지양, 원칙 준수, 공장에서 찍어낸 듯한 결과물 회피. |
| AI 제안 | 요구사항을 충족하기 위해 제안한 설계·정책 | 둥근 카드, 구체적인 서체·색상, 화면 구조, 저장 형식, 집계 범위의 추가 해석 등. 사용자 확정 사항으로 간주하지 않는다. |
| 미확정 | 원문과 사용자 지시만으로 결정할 수 없는 사항 | 다음 계획 선택법, 재완료 이력 정책, 삭제 시 보존 범위, 시간 단위와 집계 범위의 경계 등. 제안값과 결정 근거를 기록한 뒤 확정한다. |

EARS 재서술은 “시스템은 …해야 한다”, “사용자가 …하면 시스템은 …해야 한다”, “...인 동안 시스템은 …해야 한다” 형태로 조건과 관찰 결과를 드러낸다. 재서술이 새로운 제품 의무를 추가하는 근거가 되지는 않는다. 아래 원문 열과 다르게 해석될 여지가 있으면 원문을 기준으로 다시 검토한다.

| T06-C07 | 계획에 예상 시간이 저장된다. | 사용자가 계획의 예상 시간을 저장하면 시스템은 그 시간과 단위를 보존해야 한다. | 60분 등 값과 단위가 분명한 시간을 저장·조회하고 비교한다. 할 일 예상 시간과 별도의 계획값임을 함께 확인한다. |
| T06-C08 | 계획을 고쳐도 고치기 전 계획이 그대로 남아 있다. | 사용자가 계획을 수정하면 시스템은 수정 전 계획을 그대로 보존해야 한다. | 기간·우선순위·성공 기준·예상 시간을 수정하고, 수정 전 값 전체와 수정 후 값을 각각 확인한다. 보존은 필수이며 과거 버전으로 복원하는 기능은 원문 의무가 아니다. |

## 3. 원문 추적표 — 할 일 다루기

| ID | 원문 확정 — 원문 그대로 | EARS 재서술 | 관찰 가능한 인수 검사·증거 계획 |

| T06-C09 | 할 일을 만들 수 있다. | 사용자가 할 일 생성을 요청하면 시스템은 새 할 일을 생성해야 한다. | 구별 가능한 내용을 입력해 생성하고 목록·상세·저장 자료에서 새 할 일을 확인한다. |
| T06-C10 | 할 일의 내용을 고칠 수 있다. | 사용자가 기존 할 일의 내용 수정을 저장하면 시스템은 수정한 내용을 표시해야 한다. | 기존 할 일 하나를 고친 뒤 동일한 할 일의 ID와 새 내용을 확인한다. |
| T06-C11 | 할 일을 완료로 바꿀 수 있다. | 사용자가 할 일 완료를 요청하면 시스템은 해당 할 일을 완료 상태로 바꿔야 한다. | 진행 중인 할 일을 완료하고 상태 표시와 저장값을 확인한다. |
| T06-C12 | 완료한 할 일을 다시 진행 중으로 되돌릴 수 있다. | 사용자가 완료한 할 일의 되돌리기를 요청하면 시스템은 해당 할 일을 진행 중 상태로 바꿔야 한다. | 완료 상태에서 되돌리기를 실행하고 상태·돌아보기 완료 수가 현재 상태와 일치하는지 확인한다. 이력의 보존 방식은 미확정이다. |
| T06-C13 | 할 일을 지울 수 있다. | 사용자가 할 일 삭제를 요청하면 시스템은 해당 할 일을 삭제 처리해야 한다. | 할 일을 삭제하고 일반 목록 및 돌아보기 계획 수의 대상에서 빠졌는지 확인한다. 물리 삭제와 소프트 삭제 중 어느 방식인지는 원문이 지정하지 않는다. |
| T06-C14 | 할 일에 마감일을 저장할 수 있다. | 사용자가 할 일의 마감일을 저장하면 시스템은 해당 날짜를 보존해야 한다. | 식별 가능한 마감일을 저장·재조회한다. 날짜 경계 검사는 지연 집계 검사와 연결한다. |
| T06-C15 | 할 일에 우선순위를 저장할 수 있다. | 사용자가 할 일의 우선순위를 저장하면 시스템은 해당 값을 보존해야 한다. | 우선순위 저장 후 목록·상세 및 재조회 값이 같은지 확인한다. |
| T06-C16 | 할 일에 태그를 저장할 수 있다. | 사용자가 할 일의 태그를 저장하면 시스템은 해당 태그를 보존해야 한다. | 구별되는 태그를 저장하고 재조회하여 내용 일치를 확인한다. 허용 개수와 중복 처리 정책은 별도 결정 사항이다. |
| T06-C17 | 할 일에 예상 시간을 저장할 수 있다. | 사용자가 할 일의 예상 시간을 저장하면 시스템은 그 시간과 단위를 보존해야 한다. | 30분 등 값과 단위가 분명한 시간을 저장·조회하고, 해당 할 일이 포함된 예상 시간 집계와 비교한다. |
| T06-C18 | 할 일을 검색할 수 있다. | 사용자가 검색어를 입력하면 시스템은 검색 조건에 맞는 할 일을 제시해야 한다. | 서로 다른 내용을 가진 할 일을 준비하고 일치·불일치 검색어로 결과를 확인한다. 검색 대상 필드와 일치 규칙은 검사 전에 화면·명세에 확정한다. |
| T06-C19 | 할 일을 조건으로 걸러 볼 수 있다. | 사용자가 제공된 필터 조건을 적용하면 시스템은 조건에 맞는 할 일만 제시해야 한다. | 제공된 각 조건에 대해 포함·제외 사례를 준비하고 결과를 대조한다. 필터 종류와 조건 결합 방식은 AI 제안 후 확정한다. |
| T06-C20 | 화면에 밝혀 둔 기준대로 할 일이 정렬된다. | 사용자가 할 일 목록을 조회하면 시스템은 화면에 표시한 정렬 기준대로 할 일을 나열해야 한다. | 정렬이 다른 세 개 이상의 항목으로 표시 기준과 실제 순서를 비교한다. 같은 값의 항목이 있을 때 적용할 보조 기준도 구현 시 명시한다. |

| T06-C23 | 실행 기록에 시작 시각이 저장된다. | 사용자가 실행 기록을 저장하면 시스템은 해당 기록의 시작 시각을 보존해야 한다. | 날짜·시각·시간대가 구분되는 시작값을 저장하고 재조회하여 같은 순간인지 확인한다. |

| T06-C25 | 실행 기록에 실제로 걸린 시간이 저장된다. | 사용자가 실행 기록을 저장하면 시스템은 실제 소요 시간과 단위를 보존해야 한다. | 실제 시간을 저장하고 상세·서버 자료·내보내기에서 같은 값과 단위를 확인한다. 시작·종료 차이로 계산할지는 미확정 정책이다. |
| T06-C26 | 실행 기록에 막혔던 이유가 저장된다. | 사용자가 실행 기록에 막혔던 이유를 저장하면 시스템은 그 내용을 보존해야 한다. | 구체적인 막힘 이유를 저장하고 재조회한다. 이유를 적지 않은 기록의 처리 규칙은 별도 결정한다. |
| T06-C27 | 실행 기록을 저장해도 원래 계획 값은 덮어쓰이지 않는다. | 사용자가 실행 기록을 저장하면 시스템은 원래 계획 값을 변경하지 않아야 한다. | 계획의 기간·우선순위·성공 기준·예상 시간과 기존 버전을 저장 전후 비교한다. 실제 시간이나 막힘 이유로 계획값이 바뀌지 않아야 한다. |
| T06-C21 | 완료 버튼을 연달아 두 번 눌러도 완료 기록은 한 건만 남는다. | 사용자가 같은 할 일의 완료 버튼을 연달아 두 번 누르면 시스템은 그 완료에 대한 기록을 한 건만 남겨야 한다. | 진행 중인 한 항목을 빠르게 두 번 완료하고 저장된 완료 기록이 한 건인지 확인한다. 중첩 요청을 보내는 추가 반례 검사도 설계한다. 실행 기록을 완료 기록과 혼동하지 않는다. |
| T06-C22 | 그때 돌아보기의 완료 수도 정확히 1만 늘어난다. | 사용자가 진행 중인 한 할 일의 완료 버튼을 연달아 두 번 누르면 시스템은 돌아보기 완료 수를 정확히 1 증가시켜야 한다. | 직전 완료 수를 N으로 기록하고 이중 완료 후 N+1인지 확인한다. 재조회 후에도 동일해야 하며 이벤트 수를 단순 가산한 값을 쓰면 안 된다. |

## 5. 원문 추적표 — 돌아보기와 다음 계획

| ID | 원문 확정 — 원문 그대로 | EARS 재서술 | 관찰 가능한 인수 검사·증거 계획 |
| --- | --- | --- | --- |
| T06-C28 | 돌아보기의 계획 수가 그 계획에 딸린, 지우지 않은 할 일 수와 같다. | 사용자가 한 계획의 돌아보기를 조회하면 시스템은 그 계획에 속한 삭제되지 않은 할 일 수를 계획 수로 표시해야 한다. | 해당 계획의 활성 할 일, 삭제된 할 일, 다른 계획의 할 일을 섞어 준비한다. 원문에서 말하는 “계획 수”는 계획 객체 개수가 아니라 대상 할 일 개수임을 검증한다. |
| T06-C29 | 돌아보기의 완료 수가 그중 지금 완료 상태인 할 일 수와 같다. | 사용자가 돌아보기를 조회하면 시스템은 집계 대상 중 현재 완료 상태인 할 일 수를 완료 수로 표시해야 한다. | 완료·진행 중·완료 후 되돌린 항목을 준비하고 현재 상태를 직접 센 값과 비교한다. 과거 완료 이벤트의 누적 수와 분리한다. |
| T06-C30 | 돌아보기의 지연 수가 완료되지 않았고 마감일이 서울 시간 기준 오늘보다 앞선 할 일 수와 같고, 완료한 할 일을 지연으로 두 번 세지 않는다. | 사용자가 돌아보기를 조회하면 시스템은 미완료이며 마감일이 서울 기준 오늘보다 앞선 대상 할 일만 지연 수에 포함해야 한다. | 서울 기준 어제·오늘·내일 마감 항목과 어제 마감의 완료 항목을 준비한다. 미완료·어제 마감만 포함되고 완료 항목은 제외되는지 확인한다. 서울 자정 직전·직후 및 다른 브라우저 시간대에서도 검사한다. |

| T06-C33 | 돌아보기에서 정한 고칠 점 한 건이 다음 계획으로 넘어간다. | 사용자가 돌아보기에서 고칠 점 한 건을 다음 계획으로 넘기면 시스템은 그 내용을 다음 계획에 연결해야 한다. | 구별 가능한 개선점 한 건을 정하고 다음 계획에서 같은 내용을 확인한다. 어떤 계획이 “다음”인지 선택하는 기준과 중복 전달 처리는 별도 확정한다. |

시간 집계의 하위 검사 (a)·(b)·(c)는 하나의 부모 요구사항에 속한다. 요구사항 ID를 새로 만들거나 44개 조건 중 일부 의무를 생략하지 않는다. 각 하위 검사의 결과와 근거 파일을 따로 남기되, 부모 조건은 모든 하위 검사가 통과할 때만 통과한다.

## 7. 공통 해석과 미확정 정책

다음 표는 구현을 시작할 때 판단이 갈릴 수 있는 부분을 드러낸다. **AI 제안은 모두 미확정**이며 원문을 대신하지 않는다. 사용자 확정 이후 결정일과 근거를 추가한다. 표의 “원문이 정한 범위” 밖의 값은 원문에서 확정된 것으로 보고하지 않는다. 제안 정책의 관리 기준은 [프로젝트 계획의 D-01–D-13](PROJECT_PLAN.md#정책-제안과-미결정-사항)이며, 아래 표는 해당 결정의 요구사항 측면을 설명한다.

| 주제 | 원문이 정한 범위 | AI 제안 — 미확정 | 구현 전에 결정할 점 |
| --- | --- | --- | --- |
| 계획 생성과 관계 | 계획의 속성 보존, 계획에 속한 할 일, 다음 계획으로 개선점 전달이 필요하다. 계획 CRUD 전체를 독립 조건으로 나열하지는 않는다. | 계획 생성·선택 흐름을 제공하고 할 일·돌아보기를 선택한 계획에 연결한다. | 계획 제목, 생성 화면, 계획 삭제 제공 여부. 이는 기능 흐름 설계이며 새 과제 ID가 아니다. |
| 집계 기준 집합 | 계획 수는 해당 계획의 삭제되지 않은 할 일 수이고 완료 수는 그중 현재 완료 상태인 수다. | 돌아보기 전체 집계의 기준 집합을 선택한 계획의 삭제되지 않은 할 일로 통일한다. 실제 시간과 막힘은 그 할 일의 모든 실행 기록을 사용하고 계획 기간으로 추가 절단하지 않는다. | 계획 기간 밖 실행 기록의 포함 여부, 과거 계획 버전 선택 시 집계 의미. 기간에 따라 자르는 정책은 추가 확정이 필요하다. |
| 현재 상태와 역사 | 완료 집계는 지금 완료인 할 일 수이며 연속 완료는 중복 반영되지 않아야 한다. | 현재 상태는 별도로 조회하고 완료 이력은 보존한다. 되돌리기 후 재완료는 새 완료 주기로 기록하며 같은 주기의 중복 요청만 하나로 합친다. 완료 동작은 실제 수행 기록을 꾸며 만들지 않는다. | 완료 주기를 식별하는 방법, 되돌리기 이력, 화면에 이력을 보여 줄 범위. |
| 다음 계획 | 개선점 한 건이 다음 계획으로 넘어가야 한다. | 사용자가 대상 계획을 직접 선택하고 개선점 원문 및 출처 돌아보기를 연결한다. | 새 계획을 바로 만드는 흐름, 같은 개선점의 재전달 처리. |
| 마감일과 오늘 | 지연의 오늘 기준은 서울 시간이다. | 마감일은 날짜만 있는 `YYYY-MM-DD`, 오늘은 `Asia/Seoul`에서 구한 날짜로 비교한다. | 마감 시각을 별도로 둘지, 마감일 없음의 표시·필터. 날짜만 쓰면 오늘 마감은 지연이 아니다. |
| 시각 저장 | 실행 시작·종료 시각이 저장되고 새로고침 뒤 같은 값으로 복원되어야 한다. | 실행 시각은 시간대가 포함된 ISO 8601 UTC 값으로 저장하고 화면은 서울 시간으로 표시한다. | 사용자에게 시간대를 표시하는 위치, 날짜를 넘기는 실행 입력 방법. |

| 삭제와 전체 내보내기 | 할 일을 삭제할 수 있고 삭제한 할 일은 계획 수에서 제외되어야 하며 내 자료 전체를 한 파일로 내보낼 수 있어야 한다. | 소프트 삭제를 선택적 구현안으로 둔다. 채택 시 보존한 삭제 항목·연결 실행 기록도 전체 내보내기에 포함하고 삭제 상태를 명시한다. 보존 중인 계획 이력은 삭제 방식과 무관하게 내보내기에서 확인한다. | 물리 삭제 대안, 연결 기록의 보존·삭제 범위, 복구 기능 제공 여부. 소프트 삭제나 복구는 원문 의무가 아니다. |

## 8. 집계 검증용 반례와 증거

집계 숫자는 현재 자료의 결과다. 완료 이력 10건이 남아 있어도 현재 완료한 대상 할 일이 2개라면 완료 수는 2다. 과거 기록의 개수와 현재 상태의 개수를 혼합하지 않는다. 삭제를 보존하는 방식을 채택하더라도 삭제 여부를 기준 집합에서 먼저 구분한다.

통합 검사의 자료와 고정 시각은 [검증 계획의 합성 테스트 자료](VERIFICATION.md#3-합성-테스트-자료와-기준값)를 단일 기준으로 사용한다. **자동·수동 검사 전용 가상 자료**이며, 사용자의 실제 자료 제출 조건을 대신하지 않는다. 위 추적표의 작은 산식 예시는 개별 조건 설명용이며 통합 자료 A–F와 혼용하지 않는다.

통합 자료의 제안한 기준 집합은 A–E다. 서울 2026-09-10 기준 계획 수 5, 완료 수 2, 지연 수 1, 막힘 수 2, 예상 90분, 실제 55분, 차이 −35분이어야 한다. A를 진행 중으로 되돌리면 계획 수 5·완료 수 1·지연 수 2가 되며 실행 시간을 지우거나 증가시킬 이유는 없다. A를 다시 완료하면 완료 수 2·지연 수 1로 돌아간다. 완료 이벤트의 역사적 누계는 별도 값이다.

관련 반례로 빈 계획, 삭제된 항목, 다른 계획, 하나의 할 일에 여러 실행 기록, 여러 막힘 기록, 완료 후 되돌리기, 연속 완료, 서울 자정 경계, 스크립트 모양 문자열, 서버 저장 실패를 검토한다. 이 검사 목록 자체가 새로운 과제 의무는 아니다. 저장 실패의 UI 표현과 재시도 방식은 설계 제안으로 두고, 채택 시 실제 실패를 유도해 확인한다.

검증 기록에는 요구사항 ID, 하위 검사 표시(있는 경우), 사용한 데이터, 기대 결과, 관찰 결과, 통과·실패·미실행, 증거 위치, 실행 시각을 남긴다. 현재 모든 항목은 **미실행**이다. 스크린샷은 보이는 상태의 증거이고 서버 DB 보존·중복 기록 여부의 유일한 증거가 될 수 없으므로 필요한 조회 결과를 함께 연결한다.

확정된 것은 사용자의 방향이다. 이 문서의 구체적인 형태·서체·레이아웃 제안이 사용자의 최종 디자인 승인을 받은 것으로 기록되어서는 안 된다.

## 10. 완료 판정과 남은 결정

원문 ID 집합은 44개이며 추가하거나 번호를 재배정하지 않았다. 복합 조건의 하위 검사는 부모 ID에 연결한다. 구현 완료 판정은 44개 조건 각각의 실제 증거와, 제출 안내·AI 사용 기록·모든 공개 URL 검사를 함께 확인한 뒤 내린다.

다음 단계에서 우선 확정할 사항은 집계 범위, 다음 계획 지정법, 완료 주기와 삭제 보존 정책, 시간 입력·저장·표시 단위다. 사용자 실제 계획·할 일·수행 기록과 직접 판단 내역은 사용자가 제공하거나 확인해야 한다. 이 요구사항 문서는 해당 실제 자료나 시험 결과를 만들어 충족시켰다고 주장하지 않는다.

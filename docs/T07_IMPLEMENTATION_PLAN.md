# T07 인증·5일 기록 구현 계획

작성일: 2026-09-11 · 기준 T06 commit: `ae5abb4d216c28ba457665d99844e7b246598e76`

## 목표

T06 PlanDoSee의 계획·실행·돌아보기 자료를 첫 가입 계정으로 인계하고, 이메일·비밀번호 인증과 계정별 소유권 경계를 추가한다. 같은 계정 안에서 질문·지표·단위를 고정한 실제 5일 기록과 2일차 뒤 규칙 변경을 남긴다.

## 구현 단계

1. 사용자·세션·소유권·5일 기록 스키마와 T06 자료 인계 마이그레이션
2. 가입·로그인·로그아웃·비밀번호 변경·계정 삭제
3. 모든 자료 API에 현재 사용자 조건 적용 및 교차 계정 `404`
4. 로그인 화면, 계정 보안 화면, 5일 기록 타임라인 UI
5. 로컬 자동화, 보안 증거, 운영 마이그레이션·검증, 제출문 갱신

## 주요 결정

- 인증: 직접 구현한 이메일·비밀번호 인증
- 비밀번호: `bcryptjs` 3.0.3, cost factor 12
- 로그인 기억: DB 저장형 불투명 세션, 256-bit 난수 원문은 HttpOnly 쿠키에만 두고 DB에는 SHA-256 지문만 저장
- 만료: 발급 7일 뒤
- 소유권 실패: 다른 계정 자료의 존재를 감추는 `404`
- T06 인계: 첫 가입을 직렬화 가능한 트랜잭션으로 처리하고 `userId IS NULL`인 기존 계획을 그 계정에 배정

## 위험과 대응

- 직접 인증의 유지보수 위험: 비밀번호 해시는 검증된 bcrypt 라이브러리에 맡기고, 아직 없는 속도 제한·이메일 확인·복구·MFA를 제출문에 공개한다.
- 소유권 조건 누락: UI가 아닌 모든 서버 조회·수정·삭제에 `userId` 관계 조건을 두고 두 계정 양방향 E2E로 검증한다.
- 실제 관찰값 조작 위험: 앱은 구조와 규칙만 제공하며 사용자의 실제 5일 값은 임의 생성하지 않는다.
